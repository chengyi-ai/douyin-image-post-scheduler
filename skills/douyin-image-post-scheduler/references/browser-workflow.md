# Chrome 发布与核验工作流

仅在用户要求实际上传或排期时读取本文件。界面文案和 DOM 可能变化，应先检查当前页面再使用这些定位方式。

## 1. 认领现有 Chrome 标签页

- 使用用户已经登录的 Chrome 标签页，确认账号和 `creator.douyin.com` 发布页。
- 优先通过“作品发布”菜单进入“发布图文”。直接反复跳转 URL 可能回到视频标签或触发网络错误。
- 文件上传需要在点击“上传图文”之前等待文件选择事件，再一次性设置本条的全部图片。

## 2. 填写标题和正文

- 标题输入框通常可按占位符 `添加作品标题` 定位。
- 正文通常是最后一个 `[contenteditable="true"]` 编辑器。
- 如果编辑器已有内容，先聚焦后按 `Meta+A`、`Backspace` 清空，再填写。对非空 Slate 编辑器直接调用 `fill` 可能保留旧节点并造成正文重复。
- 将正文和五个原始标签一次写入；每个标签独占一行：

```text
正文最后一句。
#标签一
#标签二
#标签三
#标签四
#标签五
```

这能避免长段落软换行导致 `End` 键把话题插入正文中间。

## 3. 激活有效话题

依次处理每个标签行：

1. 找到正文编辑器中包含该标签的独立行。
2. 点击该行并按 `End`，让候选话题面板出现。
3. 从编辑器外部点击与标签完全一致的候选项。
4. 若不存在完全一致项，只能选择语义明确且以原标签开头的最接近候选项，并记录实际话题；不要静默替换成无关热门话题。
5. 每选一个都检查有效话题数量是否增加。

有效话题在当前页面通常包含 `[data-mention="#"]`，并有平台话题样式。纯文本 `#标签`、仅改变文字颜色或候选面板里出现标签都不算成功。最终断言有效话题恰好为 5 个。

若话题落入正文中间、正文字数超过 1000、或编辑器出现重复段落：停止发布；清空编辑器，重新填入正文和独立标签行。

## 4. 音乐和发布设置

- 打开“选择音乐”，切到“收藏”，选择列表中的第一首并点击“使用”。除非用户指定歌名，不要把历史歌名写死。
- 设置“不同时发布”、公开、允许保存。
- 选择“定时发布”，把 JSON 队列中的北京时间写入日期时间输入框。
- 用户修改音乐、可见范围、保存权限或排期时，以最新要求覆盖默认值。

## 5. 发布前断言

在点击“发布”前收集并核对：

- 已添加图片数量与计划一致，默认 8 张。
- 标题与队列一致且不超过 20 字。
- 编辑器内容以计划正文开头，总长度不超过 1000。
- `[data-mention="#"]` 数量为 5，并记录实际话题文本。
- 页面显示已选音乐。
- 定时时间与队列完全一致。
- 可见性、跨平台同步和保存权限符合用户要求。

断言失败时返回当前编号和失败字段，不点击发布。

## 6. 提交、续跑和最终核验

- 点击发布后等待进入 `/content/manage`；未进入则视为未确认成功，不盲目继续下一条。
- 保存每条成功结果。中断后先搜索最后一个成功标题，再从下一编号继续，避免重复提交。
- 批次结束后核对：作品总数净增量、最后一条标题、最后一条未来时间、图片数量，以及“审核中”或“定时发布中”状态。
- “审核中”说明平台已接收但尚未审核；只有页面明确显示“定时发布中”时才这样表述。

## 7. 可选录屏

仅在用户要求时录屏。先确认录制目标和保存路径，录制一条从上传到内容管理页的完整流程即可；发布完该条立即停止录屏并检查 MOV 文件存在，剩余批次继续无录屏执行。
