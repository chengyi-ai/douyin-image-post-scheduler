# 抖音图文批量排期

把本地成组图文素材转换成可恢复、可核验的抖音定时发布队列。优先复用用户已经打开并登录的 Chrome，不新开登录态。

## 开始前

1. 检查用户指定的准确素材目录和当前抖音发布页，不根据文件夹名称猜测内容。
2. 若素材符合本 Skill 的目录结构，先运行 `scripts/prepare_queue.py` 生成 JSON 队列和 Markdown 排期；不要手工重写 20 条以上的排期。
3. 需要实际控制 Chrome 时，读取 [references/browser-workflow.md](references/browser-workflow.md)。
4. 发布属于对外代表性操作。若用户尚未明确确认整批发布，先完成预检和首条草稿，在第一次点击“发布”前请求确认；整批确认后无需逐条重复询问。

## 素材约定

每条内容通常放在一个以三位编号开头的目录中：

- `01_图片内容/`：按数字前缀排序的图片。
- `02_文字内容.txt`：正文真源。
- `03_标题内容.txt`：长标题或素材标题，仅作参考。
- `04_标签内容.txt`：以 `#` 开头的话题候选。

当用户说“沿用上次工作流”时，默认使用以下已验证配置；用户的新要求优先：

- 每条 8 张图，顺序按文件名前缀。
- 发布标题取第 1 张图片文件名，去掉数字前缀和扩展名，最多 20 字。
- 正文最多 1000 字；需为 5 个有效话题预留空间，超限时只在完整句号处截断，不改写原文。
- 最多选择前 5 个话题，必须成为平台识别的有效话题，不接受普通蓝字或纯文本 `#标签`。
- 音乐选择“收藏”中的第一首。
- 公开、允许保存、不同时发布到其他平台。
- 每天 3 条，北京时间 09:00—22:00 随机分散；使用用户指定的起始日期。

## 生成队列

示例：

```bash
python3 scripts/prepare_queue.py \
  "/absolute/path/to/content-root" \
  --start-date 2026-08-24 \
  --posts-per-day 3 \
  --window-start 09:00 \
  --window-end 22:00 \
  --json-output "/absolute/path/to/douyin-queue.json" \
  --markdown-output "/absolute/path/to/douyin-schedule.md"
```

保存脚本返回的 `seed`。同一批素材需要重跑时传入 `--seed`，以保持排期不变。脚本只读取素材并写计划文件，不打开浏览器、不上传、不发布。

## 执行原则

- 按 JSON 队列顺序工作；每条提交成功后记录编号、标题、实际有效话题和排期时间，便于中断后续跑。
- 标签必须逐个激活并验证。把五个原始标签分别放在正文末尾的独立行，点击每行标签末尾，再从候选话题中选择；不得依赖长正文中的光标猜测。
- 发布前同时验证：图片数量、标题长度、正文字数、5 个有效话题、音乐、可见范围、保存权限和定时时间。
- 任一验证失败都不得点击发布。重置当前编辑器后重做该条，不在错误草稿上继续叠加。
- 每条发布后必须返回内容管理页；批次结束后核对作品总数变化，并搜索最后一条标题和时间。
- 新内容可能先显示“审核中”。区分“已提交并带未来时间”与“已转为定时发布中”，不要把审核中误报成已审核。
- 录屏只在用户明确要求时开启；通常只录一条完整自动工作流，不默认录完整批次。

## 停止条件

遇到登录失效、验证码、账号不匹配、平台拒绝排期、候选话题无法形成有效标签，或素材缺失时停止当前条目，保留已完成结果并报告准确阻塞点。不要删除、重新发布或修改已经提交的内容，除非用户明确授权。
